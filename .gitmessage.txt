# 커밋 메시지 템플릿
# ---------------------
# 접두사 규칙:
#   feat:     새로운 기능 추가
#   fix:      버그 수정
#   refactor: 코드 구조 개선 (기능 변화 없음)
#   docs:     문서/주석 변경
#   chore:    빌드, 설정, 의존성 등 잡일

# <type>: <subject>
# subject는 명령형 현재 시제로, 50자 이내로 작성
# 예: feat: add hammer hero skill

# 본문(선택) - 왜 이 변경을 했는지, 어떻게 했는지 설명
# 72자 단위로 줄바꿈 권장

# 꼬리말(선택) - issue tracker, breaking change 등
# 예: Closes #123, BREAKING CHANGE: network API updated
